# 手动添加远程规则集

“方法三：手动添加规则集”位于方法二下方。填写名称和 HTTP/HTTPS URL，从“类型”下拉框选择 `domain`、`ipcidr` 或 `Classical`，再选择目标代理组并点击右侧 `√`（导入此源）。格式由 URL 后缀自动识别，不需要手动选择。

- 仅支持 `.mrs` 和 `.yaml`；带查询参数的链接完整保留。其他后缀或无后缀地址会被拒绝并显示提示。
- MRS 支持 `domain` / `ipcidr`；YAML 另支持 `classical`。文件内容必须是相应类型的 rule-provider，不是完整的 Clash 配置。类型请按规则源说明选择，不能仅凭 YAML 后缀确定。
- 点击导入仅注册远程规则集引用，不在 SubBoost 服务端请求 URL 或解析节点，也不校验远程文件是否存在；客户端负责下载及每 86400 秒更新。
- 成功后在方法三下方的“已添加规则集”列表调整目标组、`no-resolve` 或删除，在“规则管理”调整顺序。名称和 URL 如需更换，可删除后重新添加。
- 同一目标代理组内不允许重复 URL 或重复名称，也不允许名称、URL 与该组正在使用的内置规则集冲突；不同目标代理组允许使用相同 URL 和相同名称。目标组用稳定 ID 绑定，改名不丢失引用。不同来源的内容重叠时仍按配置顺序首次匹配。
- 首次使用的英文名称会直接生成可读的 provider ID（例如 `giffgaff`），不会自动追加 `-2`。跨组重名时只为后续记录生成带目标组标识的唯一内部 provider ID，界面名称保持不变，避免最终 YAML 的全局 provider 键互相覆盖。新添加的手动规则集排在所有 `RULE-SET` 规则之前。

## 与 YAML 规则集开关兼容

现有转换入口和识别范围保持不变：先生成完整配置，再按开关转换可识别的 MetaCubeX MRS URL。域名转为 classical YAML，IP 保持 ipcidr。第三方 MRS 保持 MRS；已是 YAML 的来源保持其 URL、类型和格式，不做反向转换。转换不会修改数据库中的原始规则集。

格式与类型说明：[Mihomo 规则集合文档](https://wiki.metacubex.one/config/rule-providers/)。

## 保存、同步及备份

1. 点击 `√` 是加入当前编辑配置，**不是立即写入数据库**。与原有方法一样，仍需保存/更新订阅，或保存为模板。未保存的编辑不属于数据库备份。
2. 新的 `customRuleSets[].format` 与名称、ID、URL、类型、目标组、no-resolve 一起存入现有订阅/模板的 `encryptedConfig`，不新增数据库表，也不需要迁移。历史数据没有 `format` 时仍按 MRS 处理。
3. 读取订阅、保存后再次编辑、应用模板、登录前后配置交接和节点源刷新均保留新字段。备份恢复沿用完整数据库与密钥的现有流程，必须保留备份 `.env` 中的 `ENCRYPTION_KEY`。
4. 备份保存的是规则源 URL 与元数据，**不包含第三方远程文件的内容快照**。远程源删除或内容更改不受数据库备份保护。
5. 带有新增 YAML/classical 数据的备份或模板应在安装本补丁的版本中使用。旧版不理解新字段，降级后保存可能丢失信息；降级前请保留备份，勿用旧版覆盖这些数据。
